SentinelAX-ray 2.2.2: refreshed chunks are filtered for every player, not only the first.

- **Chunk packets shared between players are no longer changed in place.** `World#refreshChunk` (WorldEdit, region, hologram and many other plugins call it) builds ONE chunk packet and Paper sends that same object to every player watching the chunk. The line-of-sight layer used to write its rewrite into that shared packet: the first player's filter hid the ores and recorded them, and every later player on the same network thread got bytes that were already rewritten, so their filter recorded nothing and **ore in plain sight stayed stone for them** until something else resent the chunk. Players on different network threads raced on the same bytes while they were being encoded. Now the rewritten bytes go into a copy of the packet for that player only (classes on 1.21.x, the record on 26.x); the shared packet is never touched. If a future server shape cannot be copied, AX-ray falls back to the old in-place rewrite and says so once in the log.
- `ChunkFilter.hide` returns the rewritten bytes instead of overwriting its input.

Tests: 38 unit tests (new: a shared buffer gives every player the whole result and stays unchanged; packet copies of the 1.21.x class and 26.x record shapes). New live test `tools/refresh_probe.py --mode ore` with the test plugin `tools/refresh-probe`: two players on one network thread, Paper anti-xray on, three refresh rounds. AX-ray 2.2.1 fails it (the second player sees the cave ore in sight as stone after every refresh: 12/15); 2.2.2 passes 15/15 on Paper 26.3, 1.21.11 and 1.21.1, also together with SentinelAE 2.1.2.
